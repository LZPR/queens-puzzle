# 皇后 Queens

打开即玩的皇后推理小游戏：每行、每列、每个色块各放一只皇后，皇后之间不能相邻。
支持 4×4–16×16，每盘唯一解，带难度评估、逐步提示、撤销 / 重做、记录点、分享码与续玩。
棋盘上方是一条**局内信息条**（棋盘 / 用时 / 步数 / 皇后 / 难度），点哪儿都进同一个「本局信息」页。
棋盘底下是五颗按钮：**撤销 / 重做 / 记录点 / 提示 / 清空**——撤销与重做是一对（退一步 / 再走回来，
刷新后两边一起空），记录点把这一刻的棋盘存一份，推歪了点一下就回来，按住不放清空
（按钮右上角那颗「?」会说这三句话）。撤销之后棋盘上会有一圈淡淡的内描边轻轻呼吸，标出「刚才那一步动了哪几格」，
手一碰棋盘就灭。
剩最后几只皇后时，提示行会换成一个「补齐」按钮，点一下挨个落子、一段快动画收尾。
设置里是一列「拨了立刻生效」的开关；顶栏那颗回旋箭头是**新的一局**——
棋盘大小、目标难度、挑战（限时 / 步数限制 / 标错惩罚 / 禁用提示 / 禁用撤销 / 禁用记录点）都在那一层里挑，
点面板底下的「换一局」才落地；右上角那颗下载图标是**载入代码**，读剪贴板里朋友发来的
那一串，直接开那一盘。分享这一局在本局信息页里（只负责复制）。
顶栏的奖杯记战绩：每局留一张棋盘缩略图、分享码，排行榜按**限时 × 难度**分开排，
全存在本机 localStorage 里。
顶栏的调色盘是**外观**：色块可以换成几何 / 自然 / 天空 / 贴纸四套纹样，叉可以换成点，
皇后可以换成小猫，命数可以换成血条——满盘 × 看得眼花时换一套就安静了。
四类样式都由 `src/js/looks/` 里的插件提供。

开局、通关与礼炮也可在「外观」里分别选择：斜向折页 / 逐行翻页 / 涟漪折页，
镭射藏卡 / 星河藏卡，以及原版 / 爱心 / 星芒 / 安静礼炮；原版入场与保留棋盘也有对应选项。
每次通关随机获得 18 种宝可梦中的一张，顶栏的卡册按钮可查看收藏与重复数量。
卡片带彩色镭射边框，鼠标或触屏拖动可以查看角度，角色与背景分层移动；双击或 Home 回正，也可用方向键操作。
立绘使用 PokéAPI 提供的原有透明 PNG，不使用 AI 生成或改绘的宝可梦形象，来源和校验值见外观资源说明。
收藏保存在当前浏览器，刷新与换外观不重复发卡；重试并再次通关可继续集卡。
动画、卡册、专用样式和图片都在 `src/js/looks/` 内，翻格从原颜色翻到新画面，只有间隙跟随页面背景色。
每格像一本小书：左半格固定，只有中轴线以右的半格向左翻动，牌面保持原色。所有模式使用同一种翻页方向，只改变逐格推进顺序；中轴显示一条细折痕，不叠加阴影或渐变，翻页结束后折痕消失。
插件接口和目录见 [`src/js/looks/README.md`](src/js/looks/README.md)，
浏览器回归运行 `node tools/check-look-effects.mjs`；集卡检查运行 `node tools/check-pokemon-cards.mjs`。

## 局内信息

棋盘上方那一块（提示文案下面、棋盘上面）是这一局的读数，几段连成一条：

| 段 | 显示 | 说明 |
| --- | --- | --- |
| 棋盘 | `8×8` | 这一局的边长 |
| 用时 | `00:00` | 开了限时变成倒计时；最后 30 秒这一段转红慢闪 |
| 步数 | `12 步` | **这一局一共落了几次笔**，不封顶、撤销不退、刷新后还在；开了步数限制变成 `12/100`，剩 5 步内转红 |
| 皇后 | `1/8` | 放满时这一段变绿 |
| 难度 | `中等 5.2` | 圆点按分级上色；本局难度还没算出来时整段收起 |

- **步数记的是「走过的路」，不是撤销栈的深度。** 数字只增不减：撤销 / 重做是回到走过的
  位置，不算新的一步；刷新页面也照旧（它跟局面一起进存档，撤销栈则根本不落盘）。
  所以 `state.steps` 与 `view.undo.length` 是两个数，**别拿后者当读数**。
- 一次落笔 = 一步（拖动连涂一整行也只算一步，双击标 × + 放皇后算一步）。
  所以它不是格数，是「我按了几下」。计数只有一处：`app/history.js` 的 `pushHistory()`。
- 撤销栈照样有上限 `UNDO_MAX`（`core/state.js`，现在是 60）：到顶以后最早的几步撤不回去，
  但步数照涨——`60+` 那套读法在 2026-10-24 去掉了，它把「走了多少」和「能退多少」混成了一件事。
- 开了步数限制时，尾缀变成 `/100`（还剩几步一眼可见）；320px 窄屏上「步」这个字会让出去，
  但 `/60` 这种上限留着。信息条与信息页读的是同一个数。
- 开了「标错惩罚」的局，信息条下面还多出一条**命数**（红心或血条，画法在外观面板里换）。
  它不属于信息条那一个按钮：只是读数，不接点击；不惩罚的局整排 `hidden`，一点位置都不占。
- **整条是一个按钮**，点哪一段都打开同一个「本局信息」页。以前是三个胶囊
  （只有尺寸那个能点、还开到设置面板里）加提示行右侧一个难度标签：
  四种样子、三种去向，全靠记忆分辨，所以并成一条、一个入口。
- 信息页里的卡片跟信息条一一对应（棋盘 / 用时 / 皇后 / 难度），步数那张另外占满一整行——
  它答的是「这一局走到哪儿了」，跟前四项「这一局是什么样」不是同一类。
  下面是难度构成：五类推理各用了多少次、分数怎么来的。用时那张跟着心跳走，面板开着也在动。
- **难度构成只报事实，不下结论。** 那一行不写「不猜不试，纯推理就能推完」这种话——
  它跟玩家实际的推演顺序经常对不上。现在只写 `8×8 · 试推 7 次 · 纯逻辑可定 1/8 只`。
- **术语解释收在每行右端的问号里**（点开 / 悬浮 / 键盘 focus 才展开，点别处收起）。
  以前是面板底部五行常显小字，把读数挤得没地方。文案唯一出处是 `ui/difficulty.js` 的 `DIFF_ROWS`。
- **底部常显的是「读数与实际的差异」**，不是名词表：记账走的是程序的一条参考路径（不是唯一解法，
  换个起手同一只皇后可能记在别的技巧下）、`试错落子` 通常为 0（试推在 1200 次内基本都能推完）、
  分数只看边长 / 试推次数 / 开局推进率。
- 「试推次数」取 `steps.probe`（`explain()` 沿一条路径的记账），与 `假设试推 ×N` 同一个数；
  分数用的是 `analyze()` 另一次统计（上限 600 次），所以面板不给两者画等号。
- 读数卡片下面是**分享这一局**，只有一行：左边一句说明，右上角一颗**复制**图标钮
  （跟顶栏那几颗同一个圆钮样式），底下一行状态字（复制成功 / 被浏览器拦下）。
  **没有代码框**——那串码不显示、也不接受输入，点复制那一刻现算（`currentShareCode()`）。
  想自己看一眼那串码？不需要：要传给朋友的只有「复制」这一个动作。
  原来那颗「8×8」小标签也去掉了——尺寸在本页读数卡片上已经有一张。
- **这一页只负责「读」**：除了右上角的 X 与那颗复制，没有任何按钮。换盘、改难度、
  载入别人的代码都在「新的一局」那一层，所以底下原来那两颗
  「知道了」「改棋盘大小与难度」也一并去掉了（X / Esc / 点背景都能关）。
- 提示文案与信息条装在一个 `.stage-head` 里，两者一起贴在棋盘上方，
  在舞台上算**一块**：`ui/layout.js` 扣的是这一块的高度，开关浮层不会挪动棋盘。
- 落地：`#btnHud`（整条）→ `ui/difficulty.js` 的 `openDiff()`；
  各段是 `#hudSize` / `#timePill` / `#stepPill` / `#queenPill` / `#diffSeg`，
  读数由 `ui/render.js`（棋盘 / 步数 / 皇后）、`core/clock.js`（用时）与
  `ui/difficulty.js`（难度）写，样式在 `styles/base/topbar.css`。


## 快速开始

```bash
# 方式一：双击（Windows）
启动局域网游戏.bat

# 方式二：任意系统
python serve.py          # 默认 8080，被占用会自动往后找
npm start                # 同上，只是包了一层
```

> **不要直接双击 index.html。** 应用已拆成 ES 模块，`file://` 协议下浏览器会拦掉模块加载。
> 编辑器里用 Live Server 之类的静态服务也可以，只要走 http。

## 外观

顶栏第一颗按钮（调色盘）打开，是一间小展柜：每个样式摆在玻璃罩里的台子上，
下面一块名牌，选中的那间罩子亮着、名牌翻成墨底、右上角亮一枚勾。
四排各一个开关：

| 换什么 | 可选 | 说明 |
| --- | --- | --- |
| 色块 | **几何**（默认）/ **自然** / **天空** / **贴纸** / **纯色** | 前四套给每种颜色配一枚图形，压暗一档铺在格子上；纯色就是原来那块平色 |
| 叉 | **叉**（默认）/ **点** | 点是一个小圆点。16×16 满盘时，一片 × 会糊成噪点，点就安静得多 |
| 皇后 | **皇后**（默认）/ **小猫** | 小猫是同一套墨色剪影（没有底色，格子自己的色块色就是它的底），墨色脸上留一对白眼和 ω 嘴 |
| 生命 | **红心**（默认）/ **血条** | 挑战「标错惩罚」的那排命。红心是一条命一颗、失去的那颗当场碎开；血条是一条带刻度的血槽，扣命时整条缩回去 |

- 四排展柜加起来在 390×844 上比一屏高了：面板自己滚，「知道了」常开
  `position: sticky; bottom: 0` 钉在下沿——滚到哪儿都点得到它，滚到底也不会压住「生命」那排。
- 生命那排不铺在棋盘上（它是信息条下面那条读数，只有开了「标错惩罚」才露），
  所以它那块罩子用另一种底色，跟前三排分开。
- **即时生效**，跟音效 / 冲突高亮一个规矩：选完立刻写 `settings`、存盘、重画，不等「换一局」。
  跟棋盘大小 / 难度 / 挑战那套 `pending` 不是一回事。
- 换的只是**画法**，不碰 `state.marks`：局面、撤销栈、存档里的棋局都不动。
- 自动打的标记和你手标的用同一套样式（自动 / 手动本来就同款，见 `render.js`）。
  设置面板里的「自动打 ×」仍然只管**打不打**，不管长什么样。
- 顶栏那颗按钮上挂一颗小黄点，表示「现在用的不是默认那套」——不然过几天会忘了原来长什么样。
- 落地方式：`<html data-surface / data-mark / data-piece / data-life>` 是 CSS 钩子
  （`styles/panels/look.css`），格子里的画由 `game/board.js` 的 `pieceSvg()` 决定，
  色块的图形由 `game/skin.js` 铺上去，命数那条由 `ui/lives.js` 画。
- 红心与血条**两套节点同时在 DOM 里**，只由 `data-life` 切 CSS 显示——换样式不重建节点，
  正在播的碎心动画不会被换样式打断。
- 老存档没有 `surfaceStyle` 字段、或者存了认不出来的 id（插件被删了），一律按 `styleId()`
  退回各自那类的第一套（也就是几何 / 叉 / 皇后 / 红心）。

### 色块图案（四套主题）

- **一块底色一枚图形**：图案不是另找颜色画上去，而是把这块自己的颜色乘一个系数压暗
  （`palette.js` 的 `shadeOf`，tone 多在 0.045–0.07）。色相不动，远看还是那一块颜色，
  凑近才认得出是一枚什么图形。这就是「融入」，也是它能和 × 抢不到眼睛的原因。
- **每种颜色一枚**：18 个调色板下标各配一枚图形，同一盘的色块本来颜色就拉得开，
  再加一层各不相同的纹样，色弱的人也认得出是两块。
- **图形只有一层 `<defs>`**：`#skinDefs` 里每种颜色一枚 `<g>`，每格一个 `<use>` 指过去。
  换图案只改 `href` 与一个 CSS 变量，不用把 256 个格子重画一遍。
- 图形是**逐格重复**的：整块色块看过去是一片纹样。图形本身画在 20–80 之间、
  周围留白，所以格子之间有呼吸；16×16（一格二十来像素）时它退成一层几乎看不见的肌理，
  不跟棋子抢。想让图案再安分 / 再明显一点，只改插件里的 `tone`。
- **有的主题整层戴一层纱**（插件里的 `veil`，落成 `--sk-veil`）：
  贴纸那套的白边天生比别的主题亮，满盘铺开时一格格白圈会和 × 抢眼睛，
  所以整层压到 `.45`。这是**这套图案自己的属性**——空着的格子和打了叉的格子
  是同一个模样，没有「平时一套、打叉又一套」。
- 淡化（`.is-dim`）时图案跟着整格一起退掉——淡下去的意思是「这格透了、后面就是纸」，
  留一层图形就成了纸上的水印；冲突格与焦点格会连同图案一起还原。
- **底色只由色块决定，局面不许碰它**：图案的墨色是照这一块**原始底色**算死的
  （压暗或提亮一档，两者是一对），底色一动，这一对就散了。
  所以棋盘上没有「这块放好了 → 整块洗白一档」这种处理
  （以前有过：`.r-ok` + 22% 白。天空那套本来就朝纸白提亮，洗完直接跟底色贴成一片，
  整块图案凭空消失；压暗的那几套也像这块掉色了）。
  「这块有皇后了」色卡上打 ✓，棋盘上就是那只皇后本身。
  想让一块显得「放好了」，只能画在底色之上（描边 / 角标），不能改底色。

四套主题的差别只在**图形**和**往哪个方向偏**：

| 主题 | 18 枚图形 | tone | 偏法 | 观感 |
| --- | --- | --- | --- | --- |
| 几何 | 圆 / 三角 / 菱形 / 十字 / 六边形 / 竖纹 / 圆环 / 星 / 四叶 … | 0.045 | 压暗 | 规整的刻纹，最安静（默认） |
| 自然 | 叶 / 五瓣花 / 蘑菇 / 麦穗 / 蕨 / 松树 / 水滴 / 蝴蝶 / 仙人掌 … | 0.05 | 压暗 | 有机形，盘子看着软一点 |
| 天空 | 云 / 太阳 / 月牙 / 彩虹 / 闪电 / 风筝 / 彗星 / 星座 / 龙卷 … | 0.22 | **提亮** | 浮着一层薄云，最轻 |
| 贴纸 | 心 / 星 / 笑脸 / 花 / 皇冠 / 音符 / 对话框 / 爪印 … | 0.07 | 压暗 + 白边 + 纱 `.45` | 轮廓外一道浅白边，整层很轻，像裁下来贴上去又垫了张薄纸 |
| 纯色 | 无 | — | — | 什么都没有，就是原来那块平色 |

- 天空那套反着来：`ink: 'tint'` 让它走 `tintOf`（朝纸白混），像云从色块里浮出来，
  而不是凹进去。压暗的那几套在同一块浅色上容易糊，提亮反而留得住形状。
- 贴纸的「白边」是把同一份形状先画一遍白（填充与描边都白，描边 8），再压一遍本色。
  白是 **.46 半透明**、整层再戴 `.45` 的纱——0.88 时满盘白圈比别的主题都抢眼，
  0.62 时和 × 挤在一格里仍然吵，走到 .46 × .45 才是「远看有边、凑近才看出是白的」。
  面板里的预览也戴纱（开方到 .67，小盘四十来像素全戴上就糊成一片）。
- `ink` 只有 `'shade'`（默认）/ `'tint'`（天空用），`veil` 默认 1（不戴纱）。
  两类写法都见 `looks/index.js` 开头。

### 插件

外观是插件化的，都在 `src/js/looks/`：

```
looks/
├─ index.js      登记处：把插件摊平成「色块 / 叉 / 皇后 / 生命」四张表，面板和棋盘都问它
├─ classic.js    墨线：纯色、叉 / 点、皇后 / 小猫（出厂那套）
├─ geometry.js   几何：每种颜色一枚几何图形
├─ nature.js     自然：叶、花、蘑菇、麦穗、蕨、蝴蝶……
├─ sky.js        天空：云、太阳、月牙、彩虹、闪电、风筝……（唯一走提亮的）
├─ sticker.js    贴纸：心、星、笑脸、皇冠、音符、爪印……（带白边）
└─ life.js       生命：红心 / 血条（`lifes` 表；心形笔画也在这里导出，面板预览与棋盘上方共用）
```

- 一个插件可以只提供一样东西，也可以几样都给；面板按登记顺序长出展位。
  生命这类插件的字段叫 `lifes`（跟 `surfaces` / `marks` / `pieces` 一样是复数）。
- **插件名和样式名不一样时**，展位左上角挂一个小标签写插件名。现在只有「纯色」会挂
  「墨线」——另外四套的主题名就是插件名，再标一遍是重复；叉、皇后、生命三排各自
  只有一个插件，更不标。
- 加一个插件：在 `looks/` 里新建一个文件（导出一个对象），然后在 `looks/index.js`
  的 `PLUGINS` 里加一行 `import`。面板、存档兜底、CSS 都不用动。
- 色块那排是 3 列网格，现在 5 套排成两行。再加就要么排到第 3 行、要么在
  `styles/panels/look.css` 里调 `#surfaceRow` 的列数——注意它用的是 id 选择器，
  `styles/responsive.css` 里要压它的尺寸也得带 `#surfaceRow` 前缀。
- 插件里能写什么、四类各自的字段，`looks/index.js` 开头有一段完整说明；
  图形一律 `viewBox 0 0 100 100`、只给形状不给颜色（填色继承外面）。

## 填写与拖动

轻点一格打 ×，再点一次取消；同一格 340ms 内点两下就是放皇后（放下的皇后再点一下拿走）。
按住不放拖出去，就是连涂：

| 模式 | 怎么涂 | 开关 |
| --- | --- | --- |
| 按行列对齐（默认） | 起手方向定死这一笔：横向只涂落笔那一行，纵向只涂那一列 | 「拖动按行列对齐」 |
| 随意涂 | 跟着手指走，斜着、绕圈都行（指针出棋盘就停手，不往边上贴） | 同上，关掉 |

- 每一格真的涂上（不是划过去已经标过的），都会**单独震一下**：手指盖住了棋盘，
  靠这一下知道「这格算进去了」。震动跟着设置里的「震动」开关走，关掉就安静。
- 音效仍然是 40ms 一次（`paintTick`）：一整笔几十格，逐格响会糊成一片噪音；
  触觉那边本来就只有一格一下这么细，不需要节流。
- 一笔结束时才写一次盘（`endStroke` → `save()`），拖动途中不碰 localStorage。
- 开了挑战「标错惩罚」时，放到**不是解位**的格子上不算落子：格子还原成空的（那一手不
  进撤销栈、不涨步数）、红 X 拍一下、扣一条命、震一下；命扣光这局就结束了。


## 只差皇后时的一键补齐

推到最后一屏，棋盘上通常只剩皇后位是空的：一只只去找、去双击，纯粹是体力活。
这时候**提示行整行换成一个「只差 N 只皇后 · 补齐」的按钮**，点一下挨个落子，
一串快动画把棋盘收尾。

什么时候才露（`game/rules.js` 的 `pendingQueens()`，三条缺一不可）：

| 条件 | 为什么 |
| --- | --- |
| 已经放下的皇后全在解位上 | 放错位置的话，怎么补都赢不了 |
| 解位上没有被手标 × | 那种格补不进去（也不替玩家擦） |
| 棋盘上「还没标记」的格子数 = 缺的皇后数 | 保证除了皇后位，别处都已经划掉了 |

- **第三条是这件事的边界。** 没有它，一开局就满足（解位当然是空的），
  「补齐」就成了自动求解。反过来只要它成立，剩下的空格就**一定**是那几只皇后：
  每只皇后各占一行一列一块，别的皇后叉不到它的位置，所以解位永远是「活格」。
- 判据只看棋盘上**看得见**的东西（皇后、手标 ×、自动打叉画出来的 ×），
  跟「自动打叉」开不开无关：关掉以后就得自己把别处划干净，按钮才会露。
- 它长在提示行里，不是一块浮层：那是玩家一直在读的那句话的位置，不用去别处找；
  提示行高度还是 36px，**棋盘一格都不会挪**（e2e 里那条「浮层不许挪棋盘」照样成立）。
  正文在这时藏起来——按钮上已经说了「只差几只」，不必再说一遍。
- 点下去：整串**只压一个撤销点**（`pushHistory` 一次），后悔了退一步就回到补齐之前；
  落子间隔按总数摊开、整串压在一秒上下（14 只约 78ms 一只），一只一声音高往上爬的短音；
  期间 `view.filling = true`，棋盘只读，手快也抢不过动画。
- **赢还是 `checkWin()` 判的**（落满 + 无冲突 + 每块一只），跟手动落子走同一条路，
  所以这条捷径没法把一盘没解开的棋判成解开。
- 挑战里勾了「禁用提示」就不露——那一档的意思就是「全自己来」。
  开了**步数限制**时它照常露，而且整串只算一步（一次落笔）：已经推到「只差皇后」了，
  这一步就是收尾，不该按缺几只再罚一遍。
- 落地：判据 `game/rules.js` 的 `pendingQueens()` → 露不露 `ui/hint.js` 的 `setNudge()` →
  点击 `app/actions.js` 的 `fillQueens()`；样式在 `styles/base/stage.css`（`.finish-nudge`）。

## 撤销与重做

工具栏最左边是并排的一对：**撤销**（`Z` / `Ctrl+Z`）与**重做**（`Shift+Z` / `Ctrl+Y`）。
两个栈都在内存里（`view.undo` / `view.redo`，`core/state.js`），存的是整盘 `marks` + `hints` + `moves`
的快照，**都不落盘**——刷新页面回来两边一起空。

- **重做是撤销的镜像**：撤销把当前这一盘压进 `redo` 再从 `undo` 弹一份回来；重做反过来。
  所以能重做几步，取决于刚才连着撤了几步。
- **一落笔就断开**：`pushEntry()` 里 `view.redo.length = 0`。改了主意又往棋盘上落子，
  「刚才撤销掉的那条路」就作废了——这是所有编辑器的通行口径，不给「重做」留一条岔路。
- **两边都不算一步**：步数只增不减，唯一的计数点是 `pushHistory()`。撤销 / 重做是
  「回到走过的位置」，不是又走了一步（`pushRestorePoint()` 也是这个口径）。
- 撤销栈有上限 `UNDO_MAX`（60），重做栈没有单独上限——它最多也就是刚才撤出来的那几步。
- 挑战里勾了「禁用撤销」，两颗一起灰掉并挂斜纹，键盘也一起拦（`lockedHint()` 会说为什么）。

### 撤销之后的那圈残影

退回去之后人常常想不起「刚才那一笔是在说什么」，所以撤销（以及记录点的**还原**）做完，
棋盘上会有一圈**淡淡的内描边**轻轻呼吸，圈住**上一步变化过的那几格**；手一碰棋盘就灭。

- **怎么知道是哪几格**：撤销前后各拿一次整盘 `marks`，逐个比（`ui/trace.js` 的 `markTrace()`），
  撤销栈里不用另记「这一步动了哪儿」。
- **还原只亮一步**：记录点的还原跳得远，前后一比常常十几格不一样，一次全点亮反而看不出
  「记完那一刻我先走的是哪一步」。所以它还去撤销栈里找**记录之后的第一步**（`app/snap.js` 的
  `stepAfterSnap()`：撤销栈每条都存「某一步做之前的盘面」，记下那一刻的盘面后面跟着的那条，
  就是第一步做完的样子），只圈那一格的差。**只走一步时**那条「后一步」不在栈里（它就是栈顶），
  这时拿还原前的那盘当它，照样亮；一步都没走才什么都不亮。
- **画在哪**：棋盘上单独一层 SVG `#tr`（紧跟格子之后）。轮廓由 `game/geometry.js` 的
  `outlinePath()` 取这组格子的**外轮廓**：相邻两格之间那条公共边不画，一整行连成圈，
  而不是每格一个小方框。轮廓**让开半个线宽**（`--bw / 2`），笔画正好整条落在格子里面、
  外沿与格线齐平 —— 这是「内描边」而不是第二条边框：位置跟色块那条墨线重合，
  所以看着就是这一格的边界在呼吸，不会显出一道浮在里头的独立方框。
- **画成什么样**：只有**一圈线**，没有洗色、没有光晕、也没有模糊
  （`.tr-line` 用棋盘自己那套：`stroke: var(--ink)`、`width: var(--bw)`、`miter + square` 方角），
  但**整层只在 `.32–.5` 的不透明度里浅浅起伏**，变化幅度小到不会抢眼睛。
  它不抢 z-index，仍待在色块描边之下（`.rb` 是 2），提示圈画 `.gl` / `.gl-tags` 还在它上面。
  **进场终点落在呼吸的最低点**（`.32`），接不上就会在 0.24 秒处猛一暗。
  开「减少动效」就只留静态的一圈。
- **谁让它灭**：任何一次落笔（`pushEntry()`，含清空 / 一键补齐 / `Backspace`）、点任意格子（`onCell()`）、
  键盘落子（`placeQueen()`）、重做、换盘（`applyBoard()`）、开提示引导（`openGuide()`，圈画层要讲话了）。
- **重做不留残影**：往前走回刚才的位置，落点自己看得懂；再描一圈反而像在提示「下回该点这儿」。
- 读屏那一侧，撤销的播报会补一句动了哪儿（一格报坐标、多格报格数），颜色之外还有话说。
- 落地：`app/history.js`（`undo` / `redo` / `pushEntry`）→ `app/snap.js`（`restoreSnap`）→
  `ui/trace.js`（`markTrace` / `clearTrace` / `refreshTrace`）→ `ui/render.js` 的 `updateStats()`
  （两颗按钮的可用状态）→ 样式在 `styles/base/board.css` 的 `.tr` 一节。
- 测试 `tools/check-redo.mjs`（9 节：结构 / 重做语义 / 多步与改主意 / 刷新不保存 / 挑战锁定 /
  残影的格子与几何 / 还原记录点 / 键盘 / 320 窄屏）。

## 记录点

手动假设推演最难的地方不是推，是**推着推着忘了棋盘原来长什么样**。工具栏第三颗
（`重做` 与 `提示` 之间）就是给这件事准备的：把这一刻的整盘标记抄一份存着，推歪了
点一下就回来。

| 手上是什么 | 按钮长什么样 | 点它做什么 |
| --- | --- | --- |
| 还没记 | 白底、墨线书签、「记录」 | 记下这一刻（不动棋盘、不压撤销点、不涨步数） |
| 记下了 | **墨底反白**、书签填实、「还原」 | 回到记下的那一刻，记录点**用完即清**，按钮退回「记录」 |

- **只留一份，存取交替**：记 → 取 → 记 → 取。不编号、不列清单——试推的时候心里只有
  「刚才那一步之前」这一个位置，多一份记录点反而要选。
- **整个还原算撤销里的一步**（`app/history.js` 的 `pushRestorePoint()`）：撤销一下退回还原之前。
  但它**不算一步**——它没有往棋盘上落笔，跟撤销 / 重做是同一类「回到走过的位置」，
  所以开了步数限制的局不会因为回头看被罚。步数的唯一计数点仍然只有 `pushHistory()` 一处。
- **长按清空**：按住 620ms，描边上一圈红环走满（`::before` 是淡红底圈、`::after` 是
  `conic-gradient` 进度环，靠 `--hold` 推进），走满那一刻震一下、提示行说「记录点已清空」，
  按钮回到「记录」。环没走满就松手，算一次普通的点按（慢一点的点按还是点按）。
  清空只丢记录，棋盘一个字都不动。
- **「?」角标**贴在按钮右上角：点开一句话说明三种手势（长按这件事在按钮上写不下）。
  它不参与记录 / 还原，挑战禁用时点它得到的是「这局不能用记录点」。
- **说给眼睛听**：这颗角标在屏幕最底部，三句说明却写在棋盘上方的提示行里，中间隔着一整块
  棋盘（390×844 上量出来是 655px）。只把字换上去的话，视线还停在手指上，会觉得「点了没反应」。
  所以点它时有两个动作一起走：一颗光点从角标飞向提示行（380ms，先加速后减速的弧线，
  落在文字正中就化掉），同时提示行从模糊放大收到清晰（400ms）。角标自己也荡一圈涟漪，
  确认这一下按到了。光点是一次性节点（`position: fixed` 挂 body，用完 `remove()`），
  不参与布局；开了「减少动效」整段跳过，但话照样说。
- **跟存档一起落盘**：刷新页面回来还认得那一刻（撤销栈则根本不落盘）。长度对不上
  （换了尺寸的旧档 / 半截数据）一律当没有；换一局 / 重试这一局会把它清掉
  （`applyBoard()` 里 `state.snap = null`）——记录点是「这张盘上的这一刻」，换盘就没意义了。
- **不是什么都能存**：`canPlay()` 为 false 时（浮层开着、这局已封盘、补齐动画在跑）按钮是灰的。
  挑战里勾了「禁用记录点」也是灰的，并挂一层斜纹（跟禁用提示 / 禁用撤销同一个读法）。
- 存的是 `marks` + `hints` + `moves`，跟撤销快照同一份口径；还原时这几个数一起回去。
- 落地：状态 `state.snap`（`core/state.js`）→ 动作 `app/snap.js`（`saveSnap` / `restoreSnap` /
  `clearSnap`）→ 手势 `ui/snap.js`（点 / 长按 / 「?」）→ 按钮外观 `ui/render.js` 的 `syncSnap()`。

## 淡化

棋盘填到一半以后，满屏的 × 和皇后会跟还没处理的空格抢眼睛。设置面板里
有两个开关，**即时生效**（跟音效 / 冲突高亮一个规矩，不用换一局），**默认都关着**：

| 选项 | 默认 | 作用 |
| --- | --- | --- |
| 淡化 × | 关 | 手标和自动打的 × 格子整格透成背景色 |
| 淡化皇后 | 关 | 放了皇后的格子整格透成背景色 |

- 默认关掉，是因为淡下去连「这格处理过了」的分量一起没了——满盘 × 淡成一张纸，
  反而看不出自己做到哪。想要安静的棋盘再自己拨开。
- 设置存档带版本号（`SETTINGS_VERSION`，现在是 2）：老存档里「淡化 ×」是旧默认（开），
  读进来一律按新默认（关）走，别的偏好照旧保留。

- 淡的是**整个格子**：底色直接换成背景纸色（`--bg-body`），格子里的画（× / 皇后）
  再退到一档透明度。**不是把颜色掺白**——掺白只会得到一层更浅的彩色，凑近看还是一坨颜色；
  换成纸色才是「这一格透了、后面就是纸」。经纬细线留着，所以它还看得出是一格，
  只是这一格已经没有颜色了。
- **色块边线不淡**：它画在棋盘的另一层（`#rb` 那张 SVG，见 `styles/base/board.css`），
  根本不在这套 `.cell` 里。块与块的界线是解题信息，格子里填过什么是「做过的活」，
  两件事本来就该分开对待，所以格子怎么退，块界都照样清楚。
- 冲突的格子不淡（底色还原成色块色），键盘焦点落在哪一格就把哪一格还原。
- **0.5 秒防抖**：刚落下的子、刚打的叉先原样亮着，手停下来半秒才一起淡下去。
  没有这道延迟的话，连标十几格就是十几下「亮 → 暗」的闪，比不淡还吵。
  等待期间已经淡着的格子不动：新的一笔只点亮刚变的那几格，整盘不会闪一下。
- 判断只看 `state.marks` / `state.auto`（这格有没有 ×、有没有皇后），
  跟外观面板选的是哪种画法无关——以后加新外观不用动 `ui/fade.js`。
- 落地：`settings.fadeMark` / `settings.fadeQueen` + `.cell.is-dim`（`styles/base/board-states.css` 管淡成什么样，
  `DIM_DELAY` 管等多久）。续玩恢复出来的盘直接就淡着，不会先整盘亮半秒。
- 解开那一刻皇后那几格亮回来（`.board.is-won` 里那一条）：这盘棋就是奖品，不该还灰着。

## 难度与尺寸

「新的一局」面板上半部分是两个绑在一起的旋钮：**目标难度**决定「开放哪些尺寸 + 分数下限」，
**棋盘大小**在这个范围里挑。都只写 `pending`，点「换一局」才落地。

| 档位 | 开放尺寸 | 分数下限 | 实际拿得到 |
| --- | --- | --- | --- |
| 不限 | 4×4–16×16（常用 6/8/10/12/15） | — | 看尺寸和盘面，1.0–9.9 都可能 |
| 容易 | 4×4–5×5 | — | 只可能是容易（16 格、4 个色块，物理上难不起来） |
| 中等 | 6×6–8×8 | 5.5 | 中等为主，偶尔容易 |
| 困难 | 9×9–13×13 | 7.0 | 困难为主，13×13 常直接是极难 |
| 极难 | 14×14–16×16 | 8.4 | 14×14 约一半、15/16 约八成能抽到 |

- **尺寸不再是难度的另一种写法。** v2 刻度（`engine/difficulty.js` 的 `scale()`）只看
  「这盘要做多少功」：`尺寸基线 + 试推深度 + 开局卡壳`，三项各管一件事——
  边长决定「一次功有多贵」，`probes` 是「假设→矛盾」做了多少次，
  `l3Steps / n` 是开局纯逻辑推进率（0 = 第一只就得假设）。
  色块面积、邻接边数这些跟难度实测相关性 < 0.31，不再进分数。
- 后果是**跨尺寸不再严格单调**：13×13 的中位分可能低于 12×12，因为 13×13 的难度分布
  比 16×16 还宽。这是实测事实，不是 bug——信息页底部的「读数与实际的差异」里写了一条。
- **挑盘**在 `app/puzzle.js` 的 `roll()` / `search()` / `drawOne()`：一张一张生成，
  第一张分数落进档位区间 `[min, max)` 的就装（平均抽不到 2 张）。
  **两头都卡**：只卡下限的话，选「困难」会掉出一盘 8.6 的极难盘，顶栏写着极难，
  档位就名存实亡了。`min` / `max` 正好是 `levelOf` 的两个阈值，边界对齐、不重叠
  （`max` 是开区间上界，正好 8.4 算极难），极难那一档不封顶。
- **抽不到就接着抽，别先问玩家。** 一张都没落进区间时不是失败，只是手气不好：
  `search()` 会继续抽，最多替玩家等 `SEARCH_MS`（3 秒）——单张命中率只有二到五成，
  一抽空就弹卡的话，大部分时候玩家得为一个「再等半秒就有」的盘点一下按钮。
  每 `CHUNK_MS`（110ms）让出一帧，遮罩上的「已抽 N 张」才刷得出来。
- **3 秒都没抽到，才不装盘。** 棋盘保持原样，弹出「没抽到够格的盘」那一层
  （`ui/mismatch.js`），按方向分两副面孔：
  偏低（`dir='low'`，琥珀）写「还不够困难」+ 这批最高多少 + 劝放大一格尺寸；
  偏高（`dir='high'`，靛蓝）写「超出了困难」+ 这批最低多少 + 劝收小一格尺寸。
  读数先报「找了 3.0 秒、抽了 26 张」——时间才是玩家刚才实际付出的东西。
  然后只给两条路——**再抽一局**（同一档同一尺寸再来一轮，同样 3 秒）或**更换设置**
  （打开「新的一局」面板并停在这一档上，可以换尺寸或换档）。
  这一层 Esc 关不掉：关掉之后既没新盘也没旧盘，只剩一块空棋盘。
  道理很简单——目标难度是玩家设的，凑合装上一盘不合档的等于把他的设置当摆设。
- 档位区间与下限来自实测的可达性矩阵，重跑用 `node tools/scale-matrix.mjs`
  （`--per=48` 加样本）；验收用 `node tools/check-scale.mjs`。
- **老战绩**是按旧刻度打的档（13×13 那时算极难），记录里没有 `sq` 字段。
  它们在列表里留着、挂一个「旧刻度」角标，但**不进排行榜**——新旧分数不可比。
- 落地：`DIFF_BANDS` / `min` / `max`（`core/config.js`）→ `roll()` / `search()`
  （`app/puzzle.js`）→ `showMismatch()`（`ui/panels/mismatch.js`）+ `syncNew()`
  按档位夹尺寸、重建快捷尺寸按钮（`ui/panels/newgame.js`）。

## 挑战

「新的一局」面板里「换一局」上面那一组，目前有六项。**跟棋盘大小、目标难度同一个规矩：
只写 `pending`，点「换一局」才落地**——中途改完不换局就等于没改，
开了限时又反悔也不用担心这局被倒计时追着跑（面板标题会变成「挑战 · 待换一局生效」）。

| 选项 | 作用 |
| --- | --- |
| 限时 | 3 / 5 / 10 / 20 分钟挡位，本局第一次操作后开始倒计时；超时判负，结果层第一按钮是「重试这一局」（同一盘棋重开，限时不换） |
| 步数限制 | 60 / 100 / 150 / 250 步挡位（`STEP_OPTIONS`），**第 N 步落下还没解开就判负**；结果层标题「步数用尽」，中间那格读数换成「限步」 |
| 标错惩罚 | 不惩罚 / 1 / 3 / 5 / 8 条命（`LIFE_OPTIONS`）。**皇后放到不是解位的格子上**：那一手不落成（格子还原成空的、不进撤销栈、不涨步数）、红 X 拍一下、扣一条命、震一下；扣到 0 判负，结果层标题「命用完了」 |
| 禁用提示 | 「提示」按钮灰掉，键盘 `H` 也被拦住；只剩皇后时的「补齐」也不露 |
| 禁用撤销 | 「撤销」与「重做」一起灰掉，`Z` / `Ctrl+Z` / `Shift+Z` / `Ctrl+Y` 也不接（「清空」不受影响） |
| 禁用记录点 | 「记录点」按钮灰掉，`S` / `Shift+S` 也不接；推歪了只能一路撤销回去 |

这一组是**可折叠**的（标题那一行本身就是开关，右边挂着当前设定的摘要）：
摊开时三排挡位加三颗开关，收起时只剩一行，「换一局」稳稳在一屏里。
开合状态只记在面板模块的变量里——**在当前这一页有效，不落盘**。
选了「每日挑战」会自动摊开，因为那时这一组每一项都被锁住了。

那一行标题故意做得比周围的标签还重：**15px 墨色加粗、2px 墨边、暖黄底
（`--accent-soft`）+ 2px 硬阴影，右边的 chevron 装进一颗墨色小圆里**（摊开转半圈）。
它以前是一行 10.5px 的 `--ink-faint` 灰字——比旁边 14px 的行标签还小，
看上去像「区块说明」而不是按钮，也没人觉得它能点。为了让这块 32px 高的条
不至于把「换一局」顶出屏幕，展开态那三排的行距同时收了一档
（`limit-row` 4/1、`+ limit-row` 7、`switch-row` 4）：390×844 摊开后要滚的量
从 12px 降到 9px，收起来时不变。

几个刻意的取舍：

- 挑战的落地时机就是 `btnShuffle`：`commitChallenge()` 把 `pending.*` 写进 `settings.*`，
  紧接着 `newGame()` → `applyBoard()` 再把 `settings.timeLimit` 落到 `state.limit`（起算点归零）、
  `settings.stepLimit` 落到 `state.stepLimit`、`settings.lifeLimit` 落到
  `state.lifeLimit` 并把 `state.lives` 补满。
- 剩余时间 = `限时 - (已用 - state.limitFrom)`。正常开局的 `limitFrom` 是 0，
  这个偏移量只是给「同一盘重试 / 特殊情况下补开限时」留的余地。
- **切后台不扣时间**：倒计时跟着 `elapsed` 走，`elapsed` 只在页面前台时增长，跟普通计时一致。
- **步数限制靠的是「只增不减」的步数**（`state.steps`）：撤销不会把额度还回来，
  否则来回撤销就能无限刷步数，这条限制等于没开。所以那两个数是一件事的两面：
  信息条上读什么，挑战就按什么算。
- **标错的口径是「这一格是不是解位」**（`game/rules.js` 的 `isSolutionCell()`，跟
  `state.solution` 比），不是「有没有撞上冲突线」。这样判得早、判得准，而且
  「还原成空格子」不会回头被自动打叉画脏。整盘唯一解，所以这个判据是确定的。
- 放错的判定在 `app/actions.js` 的 `pushHistory()` **之前**，所以那一手压根没发生：
  不进撤销栈、不涨 `state.steps`、不涨 `moves`。双击那条路（第一下已经把 × 压进了撤销栈）
  由 `rejectQueen(i, tapped)` 把第一下那笔一起作废（弹掉撤销点、步数退回去）。
- 命数靠**记「剩几条」而不是「错了几个」**：`state.lives` 是与局面一起进存档的数，
  刷新回来还剩几条就是几条；`state.lifeLimit` 一并存，两数都在 `ui/lives.js` 里画。
- 三种判负共用一条封盘路径（`ui/win.js` 的 `failGame(reason)`），只有文案不同；
  `state.lostBy`（`'time'` / `'steps'` / `'lives'`）留着给结果层、战绩与信息页挑说法。
- 判胜之后的检查：`setMarks()` 里判完胜再判步数，最后一步既摆满皇后又正好用完步数，那是解开。
  命数则不同一侧：它在**落子之前**就判（放错那一下），所以不存在「又赢了又扣光」。
- 输掉后 `state.status = 'lost'`：棋盘只读、按钮全灰、结果层不能 Esc 掉，
  必须选「重试这一局」或「换一局新的」。想从顶栏点别的入口也行——那是主动离开这一屏，
  基座会把它强制收掉，不会留一张亮着但没人管的卡压在新棋盘上（`core/sheet.js` 的 swap）。
- 限时、起算点、步数与步数限制、命数与命数上限一起写进对局存档，刷新之后接着算
  （步数用尽 / 命用尽的那局恢复成 `playing` 后会被 `checkSteps()` / `checkLives()`
  再判一次负，刷新救不回来）。

## 每日挑战

「新的一局」面板顶上两颗标签切两种玩法：**自定义**（上面那一整套，什么都不变）与
**每日挑战**。每日挑战一天一盘，**只跟日期有关**：同一台设备、换一台设备、打几次、
刷新多少回，今天这一档都是同一盘；到了第二天日期一变，种子换一批，进度也从「容易」重来。

| 难度 | 棋盘（这一档最大盘） | 限时 |
| --- | --- | --- |
| 容易 | 5×5 | 3 分钟 |
| 中等 | 8×8 | 5 分钟 |
| 困难 | 13×13 | 10 分钟 |
| 极难 | 16×16 | 20 分钟 |

- 尺寸不另写一份表，就是 `DIFF_BANDS[tier].hi`（见 `core/daily.js` 的 `ruleOf()`）。
- 除了棋盘与限时，其余各项**写死**：步数不限、禁用提示、可以撤销、禁用记录点、
  标错扣 3 条命。面板上这些控件是 `disabled` 的，每一条下面还写一句为什么，
  不是「点了没反应」。
- **解锁链**：容易永远开着，完成前一挡才解锁下一挡。
  **打完任意一挡就算完成今日挑战**——四挡是同一天里可选的四个尺寸（5×5 想随手来一局、
  16×16 想过瘾），不是四道必须一路打穿的关卡。
- 每日挑战**不改写玩家自己的偏好**：`applyBoard(n, regions, solution, seed, vibe, rules)`
  多收一包 `rules`（限时 / 步数 / 命数 / 三把锁 / `daily`），它只落进 `state`，不碰 `settings`。
  所以打完每日再回自定义，设置还是原来那份，`settings.size` 也不会被那盘 16×16 顶掉。

实现上的几条：

- **同一挡怎么保证是同一盘**（`app/daily.js`）：`seed = FNV1a('queens-daily/日期/档位/第几次')`，
  交给 `QueensEngine.generate(n, seed)`——引擎本来就是给种子就出同一盘。
  固定尺寸的盘不一定落进同名档位（13×13 也可能只有 6.9 分，那是中等），所以顺着往后
  取最多 6 个种子，挑第一张真的属于这一档的；都试不到就用手上最后一张照常开局
  ——每日挑战不允许「今天这档开不出来」，那是 `ui/panels/mismatch.js` 才管的事。
- **记账**（`core/daily.js`）：`localStorage` 里是
  `{ days: { '2026-10-26': { hard: { ms, st, at } } } }`。**解开才记**，
  同一挡只留最快的那次（第二遍是刷时间，不是刷新记录），只留最近 400 天。
  跟战绩是**两份账**——「清空全部记录」不会把日历一起清掉。
- **这一局算不算每日挑战**看 `state.daily`（`{ day, tier }`）：它跟着存档走
  （刷新回来还是同一盘、同一个日期），重试这一局也不丢；换成自定义 / 载入分享码时
  由 `applyBoard` 清成 `null`。
- 三颗「禁用 X」以前直接读 `settings`，现在改读 `state.noHint / noUndo / noSnap`：
  它们是**这一局的规矩**，每日挑战要把它们锁死，而玩家自己的设置里可能开着。

## 结果层

解开、超时、步数用尽、命用尽共用一张卡（`.result`），按钮按结局换：

| 结局 | 主按钮 | 次按钮 |
| --- | --- | --- |
| 解开 | 再来一局（换新盘） | **重来这局**（同一盘从零再下一遍） / 看看棋盘（只收面板） |
| 超时 | 重试这一局（同一盘重开） | 换一局新的 |
| 步数用尽 | 重试这一局（同一盘重开） | 换一局新的 |
| 命用尽 | 重试这一局（同一盘重开） | 换一局新的 |

超时、步数用尽与命用尽只差标题、kicker 与中间那格读数
（`TIME UP` /「限时 3 分钟」、`OUT OF MOVES` /「限步 60」、`OUT OF LIVES` /「3 条命」）；
副标题跟着挑说法：命用尽那屏写「· 标错 3 次 · 还差 N 只皇后」，解开那屏在开了惩罚的局
也会补一句「· 标错 N 次」。

「重来这局」走的是 `retryGame()`：不重新出题，`regions` / `solution` / `seed` 原样复用，
用时、标记、撤销栈、提示计数一起归零；同一盘的战绩会再记一条。
超时那屏不给它——主按钮本来就是这件事。

## 战绩与排行榜

顶栏第三颗按钮（奖杯）打开，三个标签页：**记录 / 排行榜 / 每日挑战**。

**记录** —— 每局结束（解开或超时判负）写一条，新的在最上面。一条里有：

- 棋盘缩略图：按这盘的色块现画的 SVG（配色跟棋盘上完全一致，一眼能认出是哪盘）。
  **一块色块一条 `<path>`**，缝只留在「和别的色块（或盘外）挨着」的那几条边上：
  同色区域内部贴成一片，不会被一排横线剁成几截（一条路径里的公共边还会互相抵消，
  不留抗锯齿的细缝）
- 用时、尺寸、难度档与体感分；小字里是限时 / 限步、挑战标记、步数与结束时间
  （步数取 `st`；v3 之前的老记录没这一项，退回当时记的落子次数 `mv`；输掉的还会挂
  「超时」/「步数用尽」/「命用完了」，靠 `lr` 分）
- 点开展开：完整分享码 + 复制代码 / 复制链接 / 玩这盘 / 删除

**排行榜** —— 先按限时、再按难度分组，组内只比用时：

| 维度 | 挡位 |
| --- | --- |
| 限时 | 不限 / 3 / 5 / 10 / 20 分钟（就是 `LIMIT_OPTIONS`） |
| 难度 | 容易 / 中等 / 困难 / 极难（本局难度评估的 `tone`） |

不同限时、不同难度的时间本来就没法比（把 3 分钟的中等和 20 分钟的困难放一张表，
第一名永远属于最简单的那个），所以干脆分成 5 × 4 个独立榜单。
打开面板时默认落在**当前这一局**的组合上；胶囊上的小数字是这个组合里的成绩数。
输掉的局记在记录里但**不进榜**。

步数限制**不进分组**：它是额外约束（更难，不会更快），按用时排序照样公平；
榜单再加一个维度会把筛选项翻一倍，暂时不做。

**每日挑战** —— 一本日历，一天一格：

- 格子里四颗小点就是那天的四挡（容易 / 中等 / 困难 / 极难，跟解锁顺序一致），
  打了哪几挡就亮哪几颗；**打了任意一挡**的那天整格点亮 + 一个 ✓
  （「今天这盘算不算数」一眼看得出来）。今天那格描橙边，选中的那格描墨边。
- 顶上那行说今天的进度（`已完成 2/4`），底下那行是被选中那天的读数
  （`10月26日 · 容易 02:31 · 中等 04:12 · 完成今日挑战`）。
- 月份可以往前翻；「下个月」到本月为止就灰掉，点月份标题回到本月并选中今天。
  图例下面还有一行本月小结（`10 月完成 3 天，记下 5 挡`）。
- 数据只读 `core/daily.js`，这一页不改任何东西；标签上的角标是今天的进度（打完是 ✓）。
- 记录列表里，每日挑战那一局在难度胶囊旁边多挂一枚「每日」角标。

几条实现上的约定：

- 面板是**一整屏的页**，不是「高度跟着内容长」的底部浮层：头与标签钉在上沿，
  只有分页自己滚（`.rec-pane`）。记录会一直长、两个标签页也一高一矮，
  高度跟着内容走的话每翻一页整块面板都要跳一下。桌面上限宽 560（与 `.app` 同宽）。
- 记录只增不改：一局结束写一条，最多留 300 条（`RECORD_MAX`），超出丢最老的。
- 存的是压缩数据：色块与解各压成十六进制串（`n*n` 与 `n` 个字符），
  8×8 一条约 200 字节。分享码不存，用的时候由 `encodeShare()` 现算。
- 列表一次只画 20 条（`RECORD_PAGE`），剩下的点「显示更多」——
  300 条一起画会把面板卡住。
- 排行榜每组最多显示 12 名（`RECORD_TOP`）。
- 删除 / 清空都要点两次（第一次只是把按钮变红改字），误触不会丢数据。
- 写盘失败（隐私模式、配额满）一律静默：战绩没了也不能让正在玩的局崩掉。

### 分层与依赖方向

```
looks  ←  core  ←  game  ←  ui  ←  app
（画法） （基础设施）（棋局逻辑）（界面）（流程编排）

ui/panels/*  →  core/sheet.js（浮层基座）
ui/panels/index.js 是这些面板唯一的清单
```

- **只能向下依赖**：`looks` 谁也不引用（纯数据与画法），`core` 不引用 `game / ui / app`，
  `game` 只引用 `core / looks`，`ui` 引用 `core / game / looks`。
  `core/config.js` 只向 `looks` 要一个「默认选哪一套」，别反过来让 `looks` 认识设置。
- `events.js` 与 `main.js` 在最上层，可以引用任何模块。
- 有几处刻意保留的互相依赖，别硬拆（拆了反而更绕）：
  `ui/layout ↔ ui/guide`（重排要重画圈画层，引导翻页要重排）、
  `ui/panels/info ↔ ui/share`（信息页里要刷新分享码，载入分享码要关面板）、
  `ui/panels/newgame → ui/share`（右上角那颗载入图标读剪贴板，校验与装盘都在 share.js）、
  `ui/guide → app/actions`（点「照做」要落子，落子又要收起面板）、
  `ui/share → app/puzzle`（载入分享码其实就是换一盘棋）、
  `ui/share → core/sheet`（载入成功后收掉「当前开着的那层」，因为从哪一层发起都有可能）、
  `ui/panels/result ↔ app/puzzle`（结果层的按钮要开新局，换盘时要先收掉结果层）。
  ESM 允许循环引用，**前提是只在函数体内用对方**——不要在模块顶层求值时读对方的值。

### 样式

`index.html` 只有一行 `<link href="src/styles/all.css">`，顺序全在 `all.css` 的 `@import` 里排：

```
base/tokens → page → topbar → stage → lives → board → board-states → regions → buttons → veil
→ base/animations → sheet.css → panels/(settings → newgame → info → result → mismatch)
→ base/guide → panels/(records → look) → responsive.css
```

三条规矩：`base/` 是骨架，浮层与面板在后；**在同一元素上叠加的样式要排在它覆盖的那个后面**
（`mismatch` 压在 `result` 之后、`records` 压在 `responsive` 之前，都是这个道理）；
`responsive.css` 必须最后——它就是靠「后来居上」压前面那些固定尺寸的。

新增一段样式：属于哪个面板就写进 `panels/<面板>.css`；跨面板的小件（`.btn` / `.btn-text` /
`.switch-row` / `.switch` / `.stepper-label` / 工具栏与记录点那几颗）放进 `base/buttons.css`，浮层里共用的排版件
（`.sheet-note` / `.group-title` / `.sheet-done`）放进 `sheet.css`。顺序默认不用管，
只有「同一元素上后写的要覆盖先写的」时才需要在 `all.css` 里调整两行 import 的先后。

### 加一个浮层面板

浮层（设置 / 新的一局 / 本局信息 / 战绩 / 外观 / 结果层 / 「没抽到够格的盘」）都是**一个文件**：
markup、元素引用、事件、开关全在 `src/js/ui/panels/xxx.js` 里。加一个新的只要两步：

1. 照 `ui/panels/look.js` 抄一个文件，导出 `mount(host)`：里面先
   `host.insertAdjacentHTML('beforeend', HTML)`，再取引用、绑事件，最后
   `createSheet({ id, wrap, panel, opener, ... })`；
2. 在 `ui/panels/index.js` 的 `PANELS` 里加一行 import 和一项。

样式另外两条：在 `src/styles/panels/` 建个同名文件写自己那份，再在 `src/styles/all.css`
加一行 `@import`。**不用动** `index.html`、`core/dom.js`、`events.js`、`app/actions.js`、
`core/state.js`：
- `index.html` 只有一行 `<div id="sheets"></div>` 当挂载点；
- `canPlay()` 只看 `view.sheet`（字符串），浮层基座负责维护它；
- Esc / Tab / `inert` / `aria-expanded` / 互斥都在 `createSheet` 里，面板只声明行为。

`createSheet` 认的字段（写在文件开头也有说明）：`id`、`wrap`（整层，关时 hidden）、
`panel`（焦点与 Tab 容器）、`opener`（触发按钮）、`focusOpener`（关时焦点回不回去）、
`inert`（默认 true，整屏盖住的那两层传 false）、`beforeOpen` / `afterOpen` /
`beforeClose` / `afterClose`、`canClose(opt)`（返回 false 就 Esc / 点背景都关不掉，
只有传 `{ force: true }` 才收）、`onKey(e)`（层内额外快捷键）。

外部要开某个面板，`import` 它导出的 `openXxx()`，或者直接用基座的
`openSheet('xxx')`（不用认识那个模块）。

> 浮层壳 `.sheet` 默认是「高度跟着内容走的底部抽屉」。内容会一直长的面板（战绩就是）
> 在**自己的** `panels/xxx.css` 里把它改成整屏：`height: 100svh` / `border: 0` /
> `border-radius: 0` / `display: flex` 竖排 + 头与标签 `flex: 0 0 auto`、
> 内容区 `flex: 1 1 auto; min-height: 0; overflow-y: auto`。壳本身不用动，
> 别的面板照旧是抽屉。

> markup 是**同步**插进去的模板字符串，不要改成 `fetch('xxx.html')`：那会让启动变成
> async，`tools/` 里所有等 `__QUEENS_DEBUG__` 的断言都得改，首屏还会闪一下空面板。

## 后续打包

现在没有构建工具，浏览器原生跑 ESM。将来要打包时：

1. 以 `index.html` 为入口，Vite / Rollup 能直接吃掉这套原生模块，无需改代码
   （浮层的 markup 已经是 JS 里的模板字符串，不用 `?raw` 再引一次）；
2. `src/js/engine/` 三个文件是「经典脚本 + CJS 双模」，浏览器里挂在 `window.Queens*`、
   Node 里用 `require`（`tools/` 大量依赖）。要转成纯 ESM 时，记得同步改 `tools/` 的 `require`；
3. `index.html` 里只剩一个 `<link>`（`src/styles/all.css`），打包器会把那串 `@import`
   自动合成一份，不用手工合并 CSS。

## 约定

- 键盘：`X` 标叉、`Q`/`Enter` 放皇后、`Z` 撤销、`Shift+Z` / `Ctrl+Y` 重做、`S` 记录点（有就还原、没有就记下）、
  `Shift+S` 清空记录点、`H` 提示、`N` 新局、`Esc` 关浮层。
  挑战里禁用撤销 / 提示时，`Z` 与 `H` 只会换一句「挑战模式：这局不能…」。
- 存档键：`queens.settings.v1` / `queens.game.v1` / `queens.records.v1`（改结构要升版本号）。
- 外观存在 `settings.surfaceStyle` / `markStyle` / `pieceStyle` / `lifeStyle`，页面上表现为
  `<html data-surface / data-mark / data-piece / data-life>`；
  它只改画法，别往里塞会影响规则的东西（那属于「挑战」）。
- 面板类浮层（设置 / 本局信息 / 战绩 / 外观）打开时 `app` 会被设成 `inert`，`canPlay()` 也要一起拦——
  键盘事件挂在 `document` 上，不拦的话面板背后还能落子。
- 对局存档里的 `limit` / `limitFrom` 是挑战的限时与倒计时起点，`steps` / `stepLimit` 是
  这一局的步数与步数限制，`lifeLimit` / `lives` 是命数上限与还剩几条，`lostBy` 记的是输在哪一项上；
  老存档没有这些字段也照样读（步数按 0 起，那时没记过，编一个数比 0 更糟；
  但 `lives` 缺字段时按**满格**算——那个数编小了等于一读盘就判负）。
- 战绩每条都自带一份色块与解（`rg` / `so` 十六进制串），所以删掉最后一局的存档也不会让
  记录里的缩略图和分享码失效；读盘时逐条校验，坏掉的那条丢掉、不连累整份。
- 分享码格式：`QNS1-<边长>-<色块>-<解>-<校验>`，见 `game/share-code.js`。
