# 难度系统 v3：无限分 + 绝对阈值

> 状态：待实施  
> 范围：仅难度刻度、档位、筛选与难度展示  
> 不在本期：炼狱难度、离线分位表、种子池、100 分制、棋盘扩展、每日挑战规则

---

## 1. 目标

在不扩展棋盘、不引入离线数据的前提下，解决当前高分区间过窄的问题：

- 难度分不再截断到 9.9。
- 当前 9.0–9.9 的极难内容，主要落进新「困难」。
- 新「极难」只接受比当前更难的盘。
- 增加一个「较难」档，承接当前困难，避免中等档过宽。
- 保留绝对阈值筛选，不引入分位表或种子池。
- 炼狱档只预留概念，不实现、不显示。

## 2. 当前实现

| 位置 | 现状 |
|---|---|
| `src/js/engine/difficulty.js:460-484` | `depth` 指数 0.75；`value` 计算后截断到 1.0–9.9 |
| `src/js/engine/difficulty.js:488-500` | 四档：容易 `<5.5`、中等 `5.5–7.0`、困难 `7.0–8.4`、极难 `≥8.4` |
| `src/js/core/config.js:42-48` | 四档分数区间与尺寸区间 |
| `src/js/app/puzzle.js:104-157` | 每局最多抽 3 秒，第一张落进 `[min,max)` 的盘即接受 |
| `src/js/core/records.js` | 使用 `RECORD_SCALE=2` 区分新旧战绩 |
| `tools/check-scale.mjs`、`scale-matrix.mjs`、`check-diffpick.mjs` | 断言围绕四档、8.4、9.9 编写 |

问题根因有两条：

1. `depth` 的 0.75 次幂在高试推段严重饱和。
2. 最终分数硬截断在 9.9，超过上限的盘无法继续区分。

因此不能只改档位阈值；必须同时拉开高分公式并取消上限。

## 3. 目标刻度

### 3.1 原始分公式

保留现有 `base`、`w`、`open` 和卡壳项，只调整试推深度：

```js
var depth = Math.pow(Math.log(1 + (m.probes || 0)) / LN2, 0.90);
var value = base + 0.90 * depth * w + 0.70 * (1 - open);
```

不再使用：

```js
Math.min(9.9, value)
```

`scale()` 只保留下限与一位小数：

```js
return Math.round(Math.max(1, value) * 10) / 10;
```

本期不增加 `guessDepth` 加分项，不提高 `probeCap=600`，不修改旧 0–100 研究分 `score()`。

### 3.2 分数范围

16×16、512 盘实测：

| 指标 | 当前 v2 | 新 v3 |
|---|---:|---:|
| p10 | 6.5 | 6.6 |
| 中位 | 8.2 | 8.8 |
| p90 | 9.5 | 10.8 |
| p95 | 约 9.9 | 11.3 |
| p99 | 9.9 | 12.3 |
| 最大值 | 9.9 | 12.4 |

分数不再有固定上限；16×16 当前生成器可达到约 12.4。其它尺寸仍自然落在更低区间。

### 3.3 档位与绝对阈值

| 顺序 | key | 名称 | 分数区间 |
|---:|---|---|---|
| 1 | `easy` | 容易 | `[1.0, 6.0)` |
| 2 | `mid` | 中等 | `[6.0, 7.0)` |
| 3 | `advanced` | 较难 | `[7.0, 10.0)` |
| 4 | `hard` | 困难 | `[10.0, 11.3)` |
| 5 | `extreme` | 极难 | `[11.3, 99]` |
| — | `inferno` | 炼狱 | 不实现 |

实现时必须保证：

```js
levelOf(6.0)   === '中等'
levelOf(7.0)   === '较难'
levelOf(10.0)  === '困难'
levelOf(11.3)  === '极难'
```

四舍五入后正好落在边界上的盘，按新区间判定，不出现空档或重叠。

### 3.4 与当前难度的对应关系

16×16 同盘换算，近似如下：

| 当前内容 | 新档位 | 新分数 |
|---|---|---:|
| 当前容易 `<5.5` | 容易 | `<6.0` |
| 当前中等 `5.5–7.0` | 中等 | `6.0–7.0` |
| 当前困难 `7.0–8.4` | 较难 | `7.0–9.1` |
| 当前极难 `8.4–9.0` | 较难 | `9.1–10.0` |
| 当前极难 `9.0–9.8` | 困难 | `10.0–11.3` |
| 当前极难 `9.8–9.9` | 极难 | `≥11.3` |
| 当前被 9.9 截断的深盘 | 极难 | `11.3–12.4` |

注意：当前显示 9.9 的盘并不等价。它们有些只是刚好撞线，有些真实难度远高于 9.9；旧分数无法反推，必须由原始指标重新计算。

### 3.5 预期分布

16×16、512 盘：

| 档位 | 单张占比 |
|---|---:|
| 容易 | 4.3% |
| 中等 | 10.4% |
| 较难 | 60.4% |
| 困难 | 19.7% |
| 极难 | 5.3% |

当前 `≥9.0` 占 26.0%，新「困难 + 极难」占 25.0%，两者基本对齐。

## 4. 档位开放尺寸

`DIFF_BANDS.lo/hi` 继续同时承担“可选尺寸”和“出题尺寸范围”。

| 档位 | 尺寸 |
|---|---|
| 容易 | 4–5 |
| 中等 | 6–8 |
| 较难 | 9–14 |
| 困难 | 15–16 |
| 极难 | 16 |

说明：

- 困难与极难在 16×16 上允许重叠。
- 16×16 是唯一能稳定产出极难的尺寸。
- 尺寸区间不再要求严格互斥，相关测试和 `toneOfSize()` 兜底逻辑需同步调整。
- 不扩展 `SIZE_MAX`，分享码、存档、配色和位掩码均不受影响。

## 5. 筛选行为

沿用当前流程：

1. `newGame()` 把尺寸夹进目标档的 `lo–hi`。
2. 每张生成后计算 `vibe`。
3. 第一张满足 `band.min ≤ score < band.max` 的盘直接接受。
4. 3 秒内没有合格盘，弹出 mismatch，不装不合格盘。

本期不改：

- `SEARCH_MS = 3000`
- `CHUNK_MS = 110`
- 引擎内部按面积均衡选盘的逻辑
- 任何离线种子或分位机制

### 5.1 实测耗时

16×16 单盘生成加评估：平均 259ms、中位 188ms、p90 520ms。

| 目标 | 单张命中 | 不限时期望 | 3 秒成功 | 3 秒成功时平均 | 5 秒成功 |
|---|---:|---:|---:|---:|---:|
| 困难 `10–11.3` | 19.7% | 1.3s | 91.6% | 1.0s | 95.5% |
| 极难 `≥11.3` | 5.3% | 4.9s | 49.2% | 1.5s | 66.6% |

结论：

- 困难档可在现有 3 秒窗口内正常使用。
- 极难档有一半左右会超时；这是“不使用种子池/离线库”的已知代价。
- 本期接受该代价，不通过提高 `SEARCH_MS` 掩盖。
- 若后续要求极难稳定出盘，再单独引入长时间窗、Worker 或种子池，不放进本期。

## 6. 文件改动清单

### 6.1 `src/js/engine/difficulty.js`

- `SCALE_VERSION = 3`。
- `scaleFields()`：
  - 指数由 `0.75` 改为 `0.90`。
  - `value` 继续返回未截断值。
- `scale()`：
  - 删除 `Math.min(9.9, ...)`。
  - 保留下限 `1`。
  - 仍保留一位小数。
- `LEVELS`：
  - 增加 `{ level: '较难', tone: 'advanced' }`。
  - 顺序为 容易 / 中等 / 较难 / 困难 / 极难。
- `levelOf()`：
  - `<6.0` 容易。
  - `<7.0` 中等。
  - `<10.0` 较难。
  - `<11.3` 困难。
  - 其余极难。
- `vibe()`：
  - `scale` 自动返回 3。
  - 不改 `raw`、`tier`、`label`、`steps` 的既有含义。
  - 不把新的无限分写进 `v.raw`，避免与旧 0–100 研究分混淆。

### 6.2 `src/js/core/config.js`

- `DIFF_BANDS` 改为 5 个有效档位。
- 极难 `max: 99`，不写 `Infinity`，避免序列化与测试比较问题。
- 尺寸区间按第 4 节配置。
- `DIFF_ORDER` 增加 `advanced`：

```js
['any', 'easy', 'mid', 'advanced', 'hard', 'extreme']
```

- `bandRangeLabel()` 不需要改逻辑；`max=99` 时仍输出「11.3 分以上」。

### 6.3 `src/js/ui/panels/newgame.js`

- 难度按钮增加「较难」，顺序与 `DIFF_ORDER` 一致。
- 按钮总数变为 6（含「不限」），检查 390×844 下面板不溢出、按钮不挤压。
- 尺寸快捷行继续由 `rangeOf()` 动态生成，不新增硬编码尺寸。
- 极难只在 16×16 开放；困难允许 15–16。

### 6.4 `src/js/core/records.js`

- `RECORD_SCALE = 3`。
- `RECORD_TONES` 增加 `advanced`，顺序与难度顺序一致。
- `toneOfSize()` 在尺寸重叠时按“更高档位优先”返回；否则 16×16 的兜底记录会错误落到困难而不是极难。
- 旧记录继续通过 `sq !== RECORD_SCALE` 标记为旧刻度，不进入新排行榜。

### 6.5 难度相关展示

- `src/styles/base/topbar.css`：增加 `.hud-diff[data-tone="advanced"]` 颜色。
- `src/styles/panels/info.css`：增加 `.info-level[data-tone="advanced"]` 颜色。
- `src/styles/panels/records.css`：
  - 增加 `.rec-lv[data-tone="advanced"]`。
  - 如列表或日历会渲染 `advanced`，同时补齐对应色点。
- 分数可能从一位整数变为两位整数，`toFixed(1)` 保持不变，但需确认窄屏信息条不换行。

  - `9.9` 作为难度上限的硬编码。

## 8. 已知风险

| 风险 | 影响 | 本期处理 |
|---|---|---|
| 极难命中率仅 5.3% | 3 秒内约一半失败 | 接受，作为已知限制 |
| 较难占比约 60% | 中间档较宽 | 接受，先验证高分展开 |
| 分数超过 10 | 旧 UI/测试可能默认 1–10 | 全量排查显示与断言 |
| 16×16 尺寸重叠 | `toneOfSize` 兜底可能落错档 | 调整兜底顺序 |
| 每日挑战共用 `levelOf`/`DIFF_BANDS` | 其他玩法的档位含义会受影响 | 本期不改其规则，后续单独处理 |
| `probeCap=600` | 最顶部仍有少量并列 | 本期不动，后续再评估 |

## 10. 回退方案

- 难度公式与档位改动集中在 `difficulty.js` 和 `config.js`，可整体回退。
- `SCALE_VERSION`/`RECORD_SCALE` 保持版本隔离；回退后新刻度记录会显示为旧刻度，不会污染排行榜。
- 不涉及存档结构、分享码格式或生成器种子，回退不需要数据迁移。
